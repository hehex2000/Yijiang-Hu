# 利弗莫尔策略 · 状态转移矩阵 + churn 成本量化（②）

> 测度论视频待办 ②：把 livermore 策略的"进出场状态"建成 PMF→迁移矩阵，定量暴露 churn（频繁进出）成本——该策略的核心亏损源。
> 窗口：2018-01-01 ~ 2025-12-31（对齐 P0/①/⑤ 的 alpha 研究窗口）。配置：box 压缩验证版 `box_len=30 / box_width=0.10`（与 ⑤ 同口径）。

---

## 一、日级状态转移矩阵（{OUT=空仓, IN=持仓}）

| 昨日＼今日 | OUT   | IN    |
|-----------|-------|-------|
| **OUT**   | 93.6% | 6.4%  |
| **IN**    | 13.4% | 86.6% |

- 原始转移计数：OUT→OUT=1179，OUT→IN=80，IN→OUT=80，IN→IN=518（共 1858 个交易日）。
- **出场率 P(IN→OUT)=13.4%** → 平均持仓 **7.5 日**；**入场率 P(OUT→IN)=6.4%** → 平均空仓 **15.7 日**。
- 与《回忆录》"赚大钱是等待"自洽：策略 **67.8% 的交易日处于空仓（OUT）**，但一旦入场就**平均 7.5 日即离场**——"等待"做对了，"持有"却极短。

## 三、churn 成本量化（开费用 vs 关费用 A/B）

决策逻辑不依赖费用，故两次回测的交易序列完全一致，差距即纯交易成本拖累：

| 口径 | 总收益 |
|------|--------|
| 开费用（真实） | **+15.86%** |
| 关费用（calc_fee 置 0） | **+42.82%** |
| **churn 成本（拖累）** | **+26.96 pp** |

- churn 吞噬了 **毛收益的约 63%**（42.82% → 15.86%）。
- 占净收益比 **≈170%**（费用拖累量已超过策略净赚的全部）。
- 304 笔换手、平均持有 8.8 日、胜率 36.2%、盈利均值 +5.84% / 亏损均值 −2.82%。
- 估算单边成本率 0.225%（佣+印+滑），单笔名义 ≈20 万，累计 churn ≈ 27.4 万（基于 100 万初始）。

**判定：✅ churn 是该策略核心亏损源**——频繁进出（平均 7.5 日一轮）把毛收益吃掉近三分之二，净收益被费用反超。

## 四、⚠️ 附带发现：回测非确定性 bug（项目长期追查的根因）

两次无种子运行的 headline 数字**不一致**：

| 运行 | 交易笔数 | 开费总收益 |
|------|---------|-----------|
| 第 1 次 | 302 | +20.36% |
| 第 2 次 | 311 | +16.60% |

钉死 `PYTHONHASHSEED=0` 后两次运行**逐字节一致**（304 笔 / +15.86%），证明根因是 **`PYTHONHASHSEED` 随机化下字符串集合的迭代顺序**：

- `run_livermore_v2.py` 第 440-453 行：`cand = prev_market - set(positions) - pending_sell`（股票代码**字符串**集合）→ `cand = list(cand)` → `take = cand[:slots]`。
- 集合里是 `ts_code` 字符串，Python 对字符串做哈希随机化（`PYTHONHASHSEED`），每次进程启动集合迭代顺序不同 → `cand[:slots]` 选中的前 N 只股票不同 → 组合不同 → NAV 不同。

**这正是项目"相同参数多次回测收益率不同"bug 的真凶之一**（此前排查方向是随机种子/并发/快照时点，实际是集合切片顺序）。

**最小修复（建议，未动源码）**：第 441 行改为 `cand = sorted(cand)`，或全程对候选集排序后再切片。改后无需钉种子即得确定性结果。本报告的稳定数字即基于此修复思路（用 `PYTHONHASHSEED=0` 复现等价结果）。

> 注意：任何用 `set(...)` 对字符串键（ts_code / 行业 / 日期）做切片、取首、取样的回测代码都可能有同类隐患，建议对 `run_livermore_v2.py` 及同类脚本做一次 `set→sorted` 审计。

## 五、与 P0 / ① / ⑤ 的呼应

- **P0（尾部风险）**：利弗莫尔策略本身左尾未受控（频繁止损 + 熊市整批清仓），本报告的 churn 视角补刀——亏损不只来自单边下跌，更来自"高换手 × 固定成本"的慢性失血。
- **①（相关性税）**：利弗莫尔是单一多头策略，与三 alpha 同为 A 股权益暴露；它的问题不是分散不足，而是**自身交易太频繁**。
- **⑤（box+量能闸门）**：闸门是"少暴露"降左尾，但本报告说明——即便不闸门，利弗莫尔最大的漏勺是 **churn 成本**，而非单纯市场方向。要救该策略，优先级应是**降换手（延长持有 / 减少假突破进出）**而非加市场环境门控。

## 六、结论一句话

利弗莫尔策略"等待"做对了（68% 空仓），但"进出"做错了：平均 7.5 日一轮、304 笔换手，**churn 吃掉毛收益 63%**，是它跑不赢基准的核心亏损源；同时 `set` 切片顺序导致回测结果随进程随机，需 `sorted(cand)` 修复才能谈可靠性。
