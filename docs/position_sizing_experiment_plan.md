## 1. 结论速览（先把话说在前面）

视频**数学全对**、**行业事实有硬伤**，但它抛出了一个我们平台**恰好缺的模块**：仓位管理（sizing）。

它的致命缺陷是——**凯利（下注比例）与 2% 风险预算（单笔风险）是两套东西，视频并列讲却没建桥**。而这座桥是可以被我们的真实数据量化的，量化之后立刻暴露出视频的处方有多危险：

| 算法 | 用哪个"止损距离" | 算出的单笔仓位 |
|---|---|--:|
| 2% 风险预算 | 名义止损 **3%**（视频的隐含用法） | **66.7%** ⚠️ |
| 2% 风险预算 | 实测平均亏损 6.66% | 30.0% |
| 2% 风险预算 | 实测亏损 P95 = 18.74% | 10.7% |
| 2% 风险预算 | 实测亏损 P99 = 25.70% | 7.8% |
| 全凯利 f\*=(bp−q)/b | 实测 p=0.6266 / b=1.60 | **39.3%** |
| 半凯利 | — | 19.7% |
| 平台当前默认 | 配置 0.55/1.5 → f\*=25% 被 `max_position` 夹住 | **20.0%** |

**三个立刻可读的结论：**

1. **"2% 止损 + 2% 风险预算"在名义口径下算出 66.7% 仓位——比全凯利还激进 70%。** 视频让观众同时接受"凯利说买 20%"和"2% 规则说止损 2%"，这两句话在观众脑子里是安全的，连起来执行却是重仓。这不是学术瑕疵，是会亏钱的误导。
2. **名义止损 3% 是假的**：533 笔里 **26.64%**（142 笔）亏损超过 3%，占全部亏损笔的 **71%**。止损用前一日收盘判定、次日执行，跳空+延迟让实际亏损距离是名义值的 2~6 倍。**用名义止损做风险预算 = 系统性低估仓位风险。**
3. **平台默认 20% 恰好落在半凯利上（19.7%）**——是巧合不是设计（config 里 0.55/1.5 是"经验预设非回测实测"，见 config 注释）。这次实验会给出它该不该改的答案。

**⚠️ 2026-09-07 重大修正：上表「全凯利 39.3%」是公式误用。**

`f*=(bp−q)/b` 隐含假设**亏损时亏掉 100% 的下注额**（a=1），但本策略实测**平均亏损只有 6.657%**（a=0.0666）。换成与分布匹配的广义凯利：

| 凯利口径 | 公式 | 结果 |
|---|---|--:|
| 标准（错用，隐含 a=1） | `(bp−q)/b` | 39.3% |
| **广义（正确，a=实际亏损幅度）** | `(p·b − q·a)/(a·b)` | **590.8%** |
| 连续近似 | `μ/σ²` | **326.3%** |

实测输入：p=0.6266、平均盈 +10.652%、平均亏 −6.657%、μ=+4.189%、σ=11.331%。

→ **凯利在这套分布上给出 f\* ≈ 326%~591%，即「应加 3~6 倍杠杆」**。标准公式把亏损幅度高估了 **15 倍**，仓位被低估同量级。
→ 两个后果：
  ① 「平台默认 20% 恰好落在半凯利 19.7%」这个"巧合"**建立在错误公式上，不成立**；
  ② **凯利公式在本策略上给不出可执行答案**（>100%）。视频"凯利说买 20%"与本计划原写的"39.3%"同属**简化公式误用**——这一点视频没说错公式，是它（和当时的我）默认了 a=1 的赌场式设定，而 A 股日频策略的亏损幅度远小于 100%。

## 2. 三个核心设计决策（决定了这个实验有没有信息量）

这三条如果做错，实验会跑出一堆漂亮但零信息的数字。**先定死，再写代码。**

### D1 · 必须做**组合级共享资金池**，不能沿用"每只股票独立 10 万"

现有布林带 ablation 脚本是每只股票独立跑 10 万本金。在这套口径下比仓位是**彻底无效的**——
单标的、无并发时，仓位只是把资金等比例缩放：`f=100%` 与 `f=20%` 的**收益率百分比完全相同**，唯一区别是 80% 资金闲置。这样跑出来的对比表全是假数字。

凯利/风险预算真正要解决的问题是 **"多个同时到达的信号之间怎么分钱"**——只有在共享资金池、信号竞争资金的场景下才存在。

→ **因此 P1 需要新建一个组合级 sizing 引擎**（复用现有 `load_stock_prices` + as-of 快照管线）。

### D2 · 必须在**已验证有正期望**的策略上比，不能用负期望策略

在负期望策略上比仓位，答案永远是"越少越好"，零区分力，还会误导成"凯利有效"。

→ 载体选 **`mean_reversion` 基线**（不带任何视频候选开关）。已在 §11 验证：
单笔净期望 **+4.189%**、胜率 62.66%、盈亏因子 2.69、持仓窗口 skill **+3.670pp**（vs 等长随机窗口）。
这是平台上少数被实测证明有 alpha 的入场信号，是唯一合格的实验载体。

### D3 · 风险预算的"止损距离"必须用**实测分布**，不能用名义 3%

见 §1 第 2 条。两种口径都要跑，差异本身就是结论的一部分。

## 3. 实验设计

### 3.0 共用口径（所有档位一致，隔离单一变量 = 仓位算法）

| 项 | 取值 | 说明 |
|---|---|---|
| 载体策略 | `mean_reversion` 基线 | 全部视频候选开关 `False` |
| 股票池 | 沪深300 as-of 20190101 快照前 40 只 | 消除幸存者偏差 |
| 区间 | 2019-01-01 ~ 2026-07-31 | 与布林带系列同窗口 |
| 初始资金 | 组合级 **100 万**（共享池） | 非每只 10 万 |
| 成本 | 真实分科目（`real_cost=True`）为主口径，简单口径对照 | 佣金万2.5+滑点0.1%+过户费+日期感知印花税 |
| 出场/止损 | 完全沿用基线（Z>2 或 RSI>70 + 3% 硬止损） | **只改仓位，不改信号与出场** |
| 并发上限 | 由仓位算法自然决定（`floor(1/f)`） | 不额外设限 |

### 3.1 P0 · Bootstrap 蒙特卡洛（**先做，零回测成本**）

**输入**：现成的 533 笔 round-trip（`data/results/mean_reversion_trade_expectancy/round_trips.csv`，字段 `net_pct` / `hold`）。

**方法**：
- 按历史信号到达率（533 笔 / 40 只 / 7.5 年 ≈ **1.78 笔/只/年** → 组合约 **71 笔/年**）用泊松过程生成到达序列；
- 每笔从经验分布抽 `(net_pct, hold)`，占用 `权益 × f`，同时并发上限 `floor(1/f)`，**资金不足则跳过**（保留真实约束，这正是仓位算法的代价所在）；
- 重采样用 **stationary block bootstrap（块长 ~20 笔）**，保留 2022 熊市这类局部聚集，避免 iid 假设低估尾部；
- 每档 5000 条路径，seed 固定。

**档位**：f ∈ {满仓1.00, 0.667, 0.393, 0.30, 0.20, 0.107, 0.078, 0.05}

**输出**：每档的 终值 P5/P50/P95、**破产概率**（跌破初始 50% / 20%）、最大回撤 P50/P95、几何增长率。

**为什么先做它**：几分钟出结果、不需要新引擎，且能直接回答"满仓的尾部到底有多惨"。若 P0 就显示满仓破产概率显著、而中位数仍最高 → 结论就是"风险预算的价值在尾部不在均值"，P1 只需确认机制，不必全押。

### 3.1.1 P0 执行结果（2026-09-04，已跑通）

**核心结论（P0 能定的）：**

1. **破产概率 = 0%（全部 8 档）**。策略强正期望（单笔 +4.189%）兜底，25 年内终值从不低于初始 50%/20%。满仓档最差权益 P5 也只跌到 **71.5%** 起始资金——**视频"满仓连亏两次归零、概率 16%"是稻草人**（其 16% 建立在"每次 all-in 全亏光"的荒谬假设上；本策略最差单笔 −29.84%，永不归零）。
2. **真实风险轴 = 尾部回撤，随 f 单调**：MDD_P95 从 −3.1%（f=0.05）到 −29.8%（f=1.0）；最差权益 P5 从 98.3% 到 71.5%。风险预算/低仓位的唯一真实价值是**压尾部回撤**，不是防破产。
3. **视频处方 RISK_2PCT_NOM（66.7%）被平台 FIXED20（20%）全面压制**：终值中位 532x vs 5997x（差 11 倍）、MDD_P95 −19.9% vs −10.3%、最差权益 P5 81.2% vs 92.9%。**增长与风控双维度都劣于现状** → 视频的"2% 风险预算 + 名义 3% 止损 = 66.7% 仓位"实锤无效。
4. **iid 与 block 尾部几乎无差**（MDD 差 1~2pp，最差权益差 3~7pp，且 iid 反而略差）。计划担心的"iid 低估尾部"在 round-trip 聚合层**不成立**——每笔已是完整 round trip，日频聚类被平滑。诚实标注：P0 用 iid 也够，block 仅更稳。

**⚠️ 方法学修正（供 P1，重要）：**

- **终值不能跨 f 直接排序**：上表终值非单调（5997@f0.20 > 4582@f0.30 > 1765@f0.393 < 532@f0.667 < 7404@f1.0）。根因是**并发上限 `floor(1/f)` 把"成交笔数"与 f 耦合**：f 越小→并发越多→实际成交笔数越多（1775→1077→454→229），而笔数本身驱动终值。所以"哪个 f 终值最高"被容量机制主导，不是凯利分数主导。
- → **P1 必须用真实日历引擎算 Sharpe / 年化收益**，并强制报告「成交笔数」与「平均在市资金占比（暴露度）」。沿用布林带教训：若某档收益高但暴露度也高，须看风险调整后才成立。P0 因无日历时间轴，无法算 Sharpe，故 P0 只回答"破产/尾部回撤/视频处方是否劣于现状"三件事。
- **回撤指标 bug 已修**：首版用「全局最低权益 ÷ 全局最高」误把"起点 1.0 vs 终点 82x"算成 −99% 回撤；已改为逐时点 running-peak 相对回撤的最小值（标准最大回撤）。修正后 MDD 单调合理。

**⚠️ 2026-09-07 复核修正（P1 跑完后回看 P0，发现两处口径问题）：**

- **①「MDD_P95」被误读为尾部**：mdd 是负数，`np.percentile(mdds, 95)` 取的是**浅尾**（95% 路径好于此），不是深尾。上表该列实为浅尾；**中位回撤 `mdd_p50` 才是中心估计**：
  FULL **−39.85%** / RISK_2PCT_NOM −27.61% / KELLY_FULL −19.32% / RISK_2PCT_MEAN −16.43% / FIXED20 **−13.29%** / RISK_2PCT_REAL −8.08% / RISK_2PCT_P99 −5.91% / QUARTER_KELLY −3.84%。
  → 原结论「尾部回撤 −3.1%~−29.8%」应改为**中位 −3.84%~−39.85%**。**随 f 单调的结论方向不变**（幅度约 1.33 倍）。真正的深尾需 p5，P0 未存，待补。
- **② P0 的回撤是「round-trip 颗粒度」，系统性低估约 2 倍**：`simulate_correct` 只在**平仓时点**更新 `tot = cash + deployed`（第 94/117 行），持仓期间 `deployed` 恒定、不做逐日盯市 → 持仓内的大幅浮亏完全看不见。P1 用真实日历逐日盯市后，实现回撤普遍是 P0 中位的约 2 倍：

  | 档位 | P0 中位 MDD | P1 实现 MDD（逐日盯市） | 倍数 |
  |---|--:|--:|--:|
  | FULL | −39.85% | −66.75% | 1.7× |
  | RISK_2PCT_NOM | −27.61% | −47.55% | 1.7× |
  | FIXED20 | −13.29% | −28.02% | 2.1× |

  → **不影响的结论**：破产概率 0%、随 f 单调、视频处方劣于现状（偏误随 f 单调放大，档间差距反被**低估**）。
  → **必须注意**：P0 的绝对回撤/破产数字只可用于**档间相对排序**，不可当真实风险水位引用；「破产 0%」同样建立在 round-trip 颗粒度上。

### 3.2 P1 · 组合级 sizing 引擎 + 6 档 A/B

新建 `run_position_sizing_ablation.py`（组合级）+ 在 `base_strategy.py` 加 opt-in 的 `risk_budget` 分支（默认关，零行为变更）。

| 档位 | 仓位算法 | 名义仓位 | 机制 |
|---|---|--:|---|
| **FULL** | 每笔投入全部可用权益 | 100% | 集中，实际同时只持 1 只 |
| **FIXED20** | 固定 20% 权益 | 20% | 平台当前默认口径 |
| **KELLY_FULL** | 滚动估计 p/b → f\* | ~39% | 随胜率/盈亏比变动 |
| **KELLY_HALF** | f\*/2 | ~20% | 数值≈FIXED20 但**机制不同**（自适应 vs 固定） |
| **RISK_2PCT_NOM** | 2% ÷ 名义止损 3% | **66.7%** | 视频的隐含处方 |
| **RISK_2PCT_REAL** | 2% ÷ 滚动实测亏损距离 | ~11~30% | 修正版风险预算 |

**子扫描（敏感性）**：风险预算 ∈ {0.5%, 1%, 2%, 3%} × 距离口径 ∈ {名义3%, 滚动均亏, 滚动P95}。

**关键约束**：凯利的 p/b 必须**滚动估计**（只用 t 之前的已平仓交易），全样本 p/b 是前视。若 t 之前样本不足（<20 笔），回退到保守先验 p=0.5/b=1.5。

3. **满仓 FULL 是灾难，但不是因为破产**：CAGR −0.01% / Sharpe 0.13 / MDD −66.75%。根因是**容量饥饿**——`floor(1/1.0)=1` 使 536 个信号只成交 43 个（成交率 8.0%，skip_cap=454），单票集中暴露度 66.9%。P0「满仓不破产」成立，P1 补上后半句：**但会饿死且波动巨大**。
4. **KELLY_HALF 是唯一「收益更高且暴露度更低」的档位**：vs 平台 FIXED20 → CAGR +2.32pp、Sharpe +0.21、**暴露度 51.8% < 59.0%**；CAGR/暴露 22.13 vs 15.49。不是靠加大暴露换来的 → 按 §4 判据**初步胜出**。
   ⚠️ **2026-09-07 已被 §3.3.1 证伪**：优势实为 `floor(1/0.151)=6` 比 FIXED20 的 5 更多并发（＝更分散），朴素 `cap=8 / f=0.107` 在四个维度上全面胜过 KELLY_HALF。本条作废。
5. **⚠️ 但「成交笔数」仍是未分离的混淆变量**：各档成交率 8.0%~51.5%（并发上限 `floor(1/f)` 造成），且**均笔% 随档位变（+0.554 ~ +2.600）** → 仓位算法同时改变了「投入多少」和「能成交哪些信号」，各档选到的交易样本本就不同。**这限制了档间直接比较**，P2 须用「固定成交笔数 / 信号随机丢弃至同笔数」做二次隔离后，才能对 KELLY_HALF 下最终结论。

### 3.3 P2 · walk-forward + 部署度审计

- **滚动窗口**：5 个不重叠 ~18 个月窗口（与 OBV walk-forward 同切分），各窗口独立统计 Δ。
- **暴露度对照（沿用布林带教训）**：仓位算法本质就是**改变暴露度**。必须报告每档的「平均在市资金占比 / 平均并发持仓数」，否则"满仓收益最高"可能只是 beta。
  → 判据：**若某档收益更高但暴露度也更高，必须看风险调整后（Sharpe / 收益÷暴露度）才成立。**
- **部署率自查（方法论第13条）**：新引擎必查每次建仓实际部署额/可用资金，目标 ≈100%。等权/比例仓位最容易踩 `if cost<=cash` 整只跳过或 `cash` 循环内递减衰减的坑，这类 bug 会**悄悄改善回撤**（回撤被 bug 美化是最难自查的假数字）。

### 3.3.1 P2① · f × cap 解耦网格（2026-09-07，已跑通）

**为什么做它**：P1 里 cap 恒等于 `floor(1/f)` ⇒ f 同时改变「每笔投多少」和「能成交哪些信号」，两者纠缠。原计划的"固定成交笔数"做不干净（把笔数拉平＝抹掉仓位算法的核心后果）。改用**钉死 cap**：同一 cap 下成交的信号集合完全相同，档间差异纯粹来自 f。
**自证**：同 cap 各 f 的 `n_taken` 必须一致且 `skip_cash=0`。cap=2/3/8 ✅ 完全一致；cap=1 的 f=1.000（skip_cash=39，成交 43 vs 50）与 cap=5 的 f=0.200（skip_cash=4，223 vs 224）有现金约束介入，已标注。

**对 P3 的直接影响**：要改善的不是"仓位算法"，而是**并发上限 / 可执行信号数**（分散度）。凯利与风险预算在本策略上**均无增量信息** → 按 §3.4 纪律，**默认口径不动，不新增 `risk_budget` 开关**。

- 结论若为"风险预算优于当前 20% 固定"，新增 `risk_budget` opt-in 开关（默认 `False`），并在 config 里写明验证结论；

**凯利↔风险预算桥梁公式（本次要标定的核心产出）**：

```
仓位 = 风险预算 ÷ 止损距离          ← 风险预算法
仓位 = (b·p − q) / b                ← 凯利法
两者相等时的止损距离 = 风险预算 ÷ f*
```

用本次实测的 p/b 代入，可反解"多大的风险预算才等价于半凯利"——这是视频没打通、而我们能用数据填上的那一格。

## 6. 纪律声明

- **opt-in 优先**：所有新增开关默认 `False`，默认行为零变更；
- **单变量隔离**：各档只改仓位算法，信号/出场/成本/股票池全部共用；

- **沿用布林带教训**：regime-gate 与 walk-forward **都洗不掉 beta**，暴露度对照与部署率自查是必过关卡。
